# Bet Finder data index

The website reads `data/backtest-index.json` and never accesses the source football project at runtime.

Rebuild the index weekly from the repository root:

```powershell
C:\Users\thoma\PyCharmMiscProject\.venv\Scripts\python.exe pipeline\refresh_odds.py
C:\Users\thoma\PyCharmMiscProject\.venv\Scripts\python.exe pipeline\build_index.py --through 2026-10-01
```

The catalogue includes all 30 domestic leagues with odds or event coverage and UCL, UEL and UECL. National teams, domestic cups and non-UEFA continental cups remain outside scope. Only matches that pass the detailed-event policy enter the index; competitions with no qualifying records remain visible but unavailable.

The builder reads historical season archives and standalone CSV history, retaining only season buckets 2022-2023 onwards before calculating rolling features. Precedence is archives → legacy `Odds` loose files → `data/Odds` loose files → refreshed workspace snapshots. Refresh downloads only public CSVs to ignored `data/sources`; it never modifies the football project. Failed downloads preserve any previous snapshot and are recorded in `refresh-report.json`.

Only completed, scored fixtures dated on or before `--through` are considered. `event_quality.py` requires valid fixture identity, both XIs/formations, core statistics including xG, a timed goal sequence consistent with the final score, and a timed/attributed xG shot map with locations and counts consistent with team statistics. Missing values are never replaced with zero. Explicit own-goal timeline evidence handles older exports without a shot-level own-goal flag. Incomplete events and CSV-only rows are excluded after fixture reconciliation and before rolling features/Elo. Complete duplicate event records take precedence; CSV prices do not overwrite their validated event statistics. Early-season eligible fixtures remain in the pool, even without five prior games. Rolling form is competition- and season-specific and uses only the eligible history; missing fixtures can make it incomplete. Calendar seasons use the bucket beginning in that year (MLS 2026 → 2026-2027). Current-season buckets remain opt-in on the website.

Bookmaker maximum closing prices take precedence, with opening maximum fallback where available. If a market has no bookmaker price, the last valid Betfair decimal snapshot in [-10, 0) minutes is used. Minute zero, in-play, stale and Polymarket prices are excluded. Commission is applied by the browser to winning exchange profit using the selected assumption (5% initially). Generic event `odds_home_win` fields are not presumed to be maximum bookmaker prices.

The event archives mix provider ID namespaces. The adapter uses documented name aliases and unique fixture links anchored by a known team, competition, date and identical score; no fuzzy name matching is used. Calendar leagues permit a one-day UTC/local drift only for a unique fixture link. Canonical name identities avoid cross-provider Elo collisions. Event-only matches contribute prior history even when they have no price. UEFA exchange settlement reconstructs regulation scores from validated cumulative goal events when extra time changed the final score; uncertain regulation scores do not receive exchange fallback.

The existing 125-filter candidate catalogue is pinned in `filter_ids.json`; changes to the upstream screener do not silently introduce new filters. Source feature functions are run once at build time. `filter_quality.py` then retains only filters with at least 100 distinct matching fixtures that have at least one usable market price across all supported leagues and seasons. Multiple priced markets on one fixture count only once. No ROI or performance ranking is used. Active/retired counts and reasons are rebuilt into metadata as event coverage changes. Schema v2 uses numeric filter ordinals remapped to the active catalogue to reduce the download; existing saved strategy IDs and AND/OR semantics are unchanged. Old saved rules containing retired IDs require explicit removal before they can run, rather than silently losing a condition.

Competition metadata reports eligible and known-source fixture counts, excluded incomplete/missing-event counts, market prices, Betfair prices and latest priced dates. `eventPolicy` documents the enforced versioned requirements, and every indexed row has `eventDetailsComplete: true`. `featureCounts` separately reports conservative pre-match input availability for goals, shots, xG, Elo, XI value, lineup changes, formation, duels, weather and rest. These percentages describe eligible indexed matches and include normal rolling-history warm-up gaps; they are neither individual filter hit rates nor an independent reconciliation of every scheduled fixture. Weather and market values remain optional. The requested cutoff must not be presented as proof of complete coverage in every source. Missing prices are excluded from returns and surfaced in results.

## Approved event backfills

Run `python pipeline/audit_events.py` first. It reads existing archives plus the alternate EPL FotMob archive and workspace event cache, and writes an ignored per-file audit to `data/sources/event-audit.json`. Raw file counts may include duplicate provider records; the index builder performs the unique-fixture reconciliation.

`python pipeline/backfill_events.py --approved-access --pilot 3` samples up to three missing fixtures per competition/season, spread across time. It uses the existing pure FotMob parsers with a normal HTTP transport, validates the returned season, match ID, date, team IDs and score, and never relabels a mismatched current shell as an old match. Use only under provider-approved access; this flag is an explicit precondition, not permission granted by the software. One request is active at a time (one-second minimum interval by default). HTTP 401/403/429 stops the whole run, with no bypass or alternate endpoint attempts.

Remove `--pilot` for a resumable gap backfill; `--competition`, `--season` and `--max-details` can bound it. Validated records go only to ignored `data/sources/events/<code>/<season>/<match-id>.json`. Attempt outcomes and run reports are in `data/sources/fotmob/`; rejected incomplete responses are not loaded by the index. Rejections are skipped on resume unless `--retry-rejected` is explicitly set. No credentials, raw API responses or local paths are included in the public match index, and no football-project files are modified. Re-run the audit after adding files, then rebuild the index and deploy.

The browser shows a separate, full-width filter-selection step before results. Filter-card counts are recalculated for the chosen market, leagues and seasons before rule combinations. A globally retained filter may have fewer than 100 matches in a narrower scope; positive small samples are labelled and zero-match options are disabled unless already selected.

`guard_history_gaps` retains excluded fixtures only as known chronology markers. It invalidates five/ten-game rolling fields and their combined derivatives when a required preceding fixture lacks complete details. Previous-lineup/formation/red-card and XI-value change comparisons cannot skip a missing prior fixture either. These markers never enter the public match pool or supply feature statistics; fixtures absent from every source cannot be detected by this safeguard.

The adapter currently calls the proven feature functions in the source project during the weekly build. Its JSON output contract deliberately isolates this dependency so those functions can be migrated into this repository category-by-category without changing the website.
